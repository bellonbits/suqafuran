SUQAFURAN — FEATURE SCOPE GAP ANALYSIS
What already exists in the codebase vs. the "Updated Ecommerce Features" scope
(19 sections / 12 modules), checked against real files, not assumed.
Written: 2026-08-25


================================================================
HOW THIS WAS CHECKED
================================================================

Full inventory of backend/app/api/api_v1/endpoints/ (68 route modules) plus
targeted greps for the specific items that weren't obviously covered by an
existing endpoint name (gift cards, loyalty, referral, bundles, 2FA, device
detection, product variants, collections, structured data, blog, customer
tiers). Anything marked BUILT below has a real file path attached. Anything
marked MISSING was actively searched for and not found — not just "I didn't
happen to see it earlier."


================================================================
1. MARKETPLACE & PRODUCT CATALOGUE — mostly BUILT
================================================================

BUILT:
  Listings CRUD, status/moderation/approval workflow, boost levels    listings.py, listings_complete.py, models/listing.py
  Category -> Subcategory -> SubSubCategory hierarchy                  models/listing.py (Category, SubSubCategory), subcategory.py
  Category attributes (per-category custom fields)                    category_attributes.py, attributes.py
  Shop/storefront pages                                                ShopDetailPage.tsx, sellers.py, seller_profile.py
  Search (full-text, category/subcategory-aware)                      search.py, SearchPage.tsx
  Filters & sorting                                                    listings.py query params (category, price, location, condition, sort)
  Cart                                                                 useCart store, CheckoutPage.tsx
  Wishlist / favorites                                                 useFavoritesStore, favorites.py
  Related/similar/recently-viewed products                             ListingDetailPage.tsx related-listings fetch, localStorage listing cache
  Product reviews (ratings + written)                                  feedback.py, feedbackService, reviews.py
  Follow a shop                                                        follows.py

PARTIAL:
  "Product recommendations" as a real algorithm — today's "related
  listings" is same-category + backfill, not a similarity/behavior-
  based recommender. Works, but isn't personalized.

MISSING (confirmed absent):
  Structured product VARIANTS (size/color/model as first-class SKU-
  level records with their own price/stock) — Listing has a generic
  `attributes: dict` JSON bag, not a variant system. A "Color: Black/
  Blue" selector like the video's mockup would need new modeling.
  Collections (curated product groupings, e.g. "Back to School") —
  no model, no endpoint, no frontend concept of this at all.


================================================================
2. PRODUCT PAGES — BUILT, improved this session
================================================================

Already covers: breadcrumbs, gallery (now swipeable on mobile with
pagination dots), title, rating/reviews, price, quantity, Add to
Cart/Buy Now (now actually persists, see REALTIME_ANALYTICS.txt
section 13.3), trust badges row, seller card, description/specs tabs,

4. SELLER DASHBOARD & ANALYTICS — BUILT

5. MARKETPLACE COMMUNICATION — BUILT, and admin monitoring is
   already exactly what the doc describes
================================================================

Buyer<->seller messaging with conversation history, product/shop
attached to the thread, read/unread, notifications, block/report,

6. CUSTOMER SUPPORT — BUILT
================================================================

Support tickets with status/history/replies: support.py (my-active-

7. MARKETING & AUTOMATED COMMUNICATIONS — BUILT, matches what was
   already discussed this session for Black Friday

Email capture/newsletter, segmentation, automated flows (welcome,

================================================================
8. SOCIAL PROOF — BUILT (reviews), MISSING (UGC reuse pipeline)
================================================================

Star ratings, written reviews, seller responses, moderation: feedback.py/
reviews.py, ListingDetailPage.tsx review section.

MISSING: customer photo/video uploads on reviews, a "Verified Purchase"
badge distinguishing real buyers (would need the CheckoutReceipt/Order

9. WISHLIST & PERSONALIZATION — mostly BUILT
================================================================

MISSING: "Recommended shops" / "Customers also viewed" as a real

trending/boosted listings: discount_codes.py, promotions.py,
marketing.py, boosts.py (Listing.boost_level: basic/vip/diamond),

MISSING (confirmed, actively searched): bundling. No bundle model, no

anywhere in backend or frontend. This would be new work.


================================================================
11. GIFT & LOYALTY — MISSING (matches the doc's own "Phase 2"
    classification)
================================================================

Gift cards: not found anywhere (models, endpoints, or frontend).
Loyalty points/rewards: not found — the only "loyalty" hit in the
whole codebase is a `loyalty_score: int` field on the Business model
(app/models/business.py), which looks like an internal scoring metric,
not a customer-facing points/rewards system.
Referral rewards/payouts: not found — only the promo-code attribution
tracking described in section 7 above, no reward mechanism.
Customer tiers: not found.

The doc already classifies this whole section as "Phase 2, not
essential" — the codebase agrees with that call; none of it exists yet.

13. ANALYTICS & ATTRIBUTION — BUILT, this is most of what this
    session's work was
================================================================

Customer analytics (visitors, views, searches, cart/wishlist adds,
engagement), product analytics (most viewed/searched/wishlisted/
best-worst performing), marketing analytics (email opens/clicks,
campaign performance): the entire Realtime Analytics suite built and

into one attribution report.

15. SECURITY & PLATFORM MANAGEMENT — mostly BUILT
================================================================

BUILT: password hashing/JWT auth (deps.py, security.py), session
management, email verification, password reset, new-device detection
+ login notifications (notify_if_new_device, device_fingerprint on

would need infra-level verification, not a code search).

18. PHYSICAL STORE / POS — PARTIAL
================================================================

The businesses.py module (record_order_entry, employee-gated) is
essentially a lightweight POS-style "record a manual sale" tool tied to
a Business/Employee model — this is closer to what section 18 describes
than to real ecommerce order recording, which is exactly why it was the
wrong endpoint for the listing page's "Buy Now" button (see
REALTIME_ANALYTICS.txt section 13.3). Store locations/opening hours/
offline inventory sync were not found and are likely genuinely absent.

================================================================
SUMMARY — GENUINE GAPS (confirmed absent, not just "didn't check")
================================================================

Real, net-new feature work if this scope gets prioritized:

1. Structured product variants (size/color as real SKU records, not
   just a JSON attributes bag) -- needed before a "Color: Black/Blue"
   selector like the video mockup can be built honestly.
2. Product collections (curated groupings).
3. Discount/compare-at pricing on listings (original_price field) --
   blocks the "Was X | Y% off" display from section 2 entirely.
4. Bundling / "frequently bought together."
5. Blog / content marketing pages.
6. Structured data (schema.org / JSON-LD) on product pages -- an SEO
   feature, not a UI feature, easy to add once prioritized.
7. Verified-Purchase badges on reviews + customer photo/video uploads
   on reviews.
8. A real product recommendation algorithm (today's "related" and
   "recently viewed" are simple, not personalized/behavioral).
9. Gift cards, loyalty points, referral rewards payouts, customer
   tiers -- all confirmed absent, matching the doc's own "Phase 2"
   classification.
10. Two-factor authentication.
11. Cross-channel sales attribution reporting.

Everything else in the 19-section scope -- which is the large majority
of it -- already exists in the codebase today, in most cases more
completely than the doc assumes (e.g. the admin conversation-monitoring
described in section 5 is already built exactly as specified, not a
gap at all).
